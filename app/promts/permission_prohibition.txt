для посетителя должно существовать 2 страницы:
-запрет на рассылку сообщений с ресурса на указанный телефон/email
-разрешение на рассылку сообщений с ресурса на указанный телефон/email
на странице указываются контактные данные телефон/электронная почта на которые посетитель может дать разрешение или установить запрет на рассылку.
алгоритм установки запрета/разрешения следующий:
-пользователь указывает канал: телефон/почту
-в зависимости от выбранногго канала предлагается ввести номер телефона или адрес электронной почты
-пользователь указывает номер телефона или почту и нажимает кнопку Получить код
-фронт сервиса проверяет корректность указанных параметров. если не корректно, то сообщает об этом пользователю до тех пор пока пользователь не исправит ошибку. Телефоны можно вводить исключительно российские!!
-фронт после того как проверил, что данные введены корректно, отправляет запрос на генерацию кода. отправляемые данные в запросе: вид контакта, значение контакта(номер телефона или адрес почты), статус запрет/разрешение(в зависимости от того, на какой странице находится посетитель)
-бэкенд получив запрос, проверяет его корректность. если данные окрректны, то идм дальше по алгоритму
-бэкенд по входным параметрам тип канала+значение контакта проверяет есть ли такой контакт, если такого контакта нет, то его создает.
-проверяет есть ли у контакта на данный момент запрет/разрешение. 
-если есть запрет/разрешение(PermissionProhibition.status=ACTIVE), то сравнивает с тем, который посетитель пытается установить. если они одинаковые, то возвращает фронту сообщение, что такой запрет/разрешение ранее был установлен для такого вида контакта. 
-если не одинаковые статусы запроса и установленного запрет/разрешение, то проверяет есть ли на данный момент активный верфикационный код? если есть, то отправляет фронту сообщение, что ранее был отправлен верификационный код до конца активации которого осталось столько то времени. если аткивного кода нет, то генерирует новый верификационный код, отправляет его на указанный контакт и отправляет фронту ответ, что код отправлен, до конца его активации осталось столько то времени.

Шаг 1: Запрос кода (POST /api/v1/permissions/request-code)
Входные данные: channel_code: ChannelType, value: str, status: PermissionType (желаемое действие: ALLOWED или BLOCKED).

Нормализация: Значение телефона приводится к формату E.164 (+7XXXXXXXXXX). Проверяется соответствие кодам РФ (+79...).

Проверка рейт-лимита: Подсчитывается количество кодов в таблице verification_codes для этого value за последний час. Если их ≥10, запрос отклоняется с кодом 429 Too Many Requests.

Поиск или создание контакта:

Выбирается S_ChannelIdentifier с channel.code == channel_code и is_default == True.

Если найдена запись со статусом ACTIVE:

Если её type совпадает со status из запроса, возвращается ответ: «Данное правило уже установлено ранее».

Если не совпадает — переходим к этапу верификации.

Проверка активного кода:
Ищется запись VerificationCode по contact_id, где used == False и expires_at > now().  
PY

Если код найден: Возвращается ответ с остатком времени: «Код уже отправлен. Повторный запрос возможен через X сек.» (генерация нового блокируется на все время жизни текущего).

Если активного кода нет:

Генерируется случайный 6-значный цифровой код.

Создается запись VerificationCode с expires_at = now() + timedelta(minutes=5).  
PY

Создается или обновляется единственная черновая запись PermissionProhibition для контакта: status = DRAFT, type = status_из_запроса, verification_code_id = code.id.

Отправляется SMS через провайдера.

Клиенту возвращается статус 200 OK с сообщением о доставке и временем жизни кода (300 секунд).

Шаг 2: Подтверждение кода (POST /api/v1/permissions/confirm-code)
Входные данные: value: str, code: str.

Поиск контакта: По нормализованному значению value находится Contact. Если контакт не найден — ошибка 404 Not Found.  
PY

Поиск активного кода:
Выбирается последний VerificationCode для данного contact_id, где used == False и expires_at > now().  
PY

Если запись отсутствует — ошибка 400 Bad Request («Срок действия кода истек или он не запрашивался»).

Проверка количества попыток ввода:

Если verification_code.attempts >= 5, код деактивируется (used = True), а посетителю возвращается ошибка: «Превышено максимальное число попыток ввода. Запросите код заново».  
PY

Сверка кода:

Код не совпал: Инкрементируется счетчик verification_code.attempts += 1, изменения сохраняются в БД. Возвращается ошибка 400 Bad Request («Неверный код. Осталось попыток: X»).

Код совпал:

Помечаем код использованным: verification_code.used = True.  
PY

Находим черновик PermissionProhibition по contact_id.  
PY

Переводим правило в активное состояние: status = ACTIVE, confirmed_at = func.now().  
PY

Фиксируем транзакцию (db.commit()).

Возвращаем фронту статус успешной установки правила (ALLOWED или BLOCKED).
